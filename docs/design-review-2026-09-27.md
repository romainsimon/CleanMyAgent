# Native design and motion review

User mandate: apply https://github.com/emilkowalski/skills to the website and native app, and substantially improve the app. Official source pinned to d16ebe60d09a5ba2afcb7054ede9d0a10c9f6128. Skills used: emil-design-eng, apple-design, write-swift and review-animations, with the established Impeccable native Operate context.

| Before | After | Why |
| --- | --- | --- |
| Every navigation item has an icon tile and selection outline | Hierarchical SF Symbol, one selected surface, sentence-case groups | Make the destination easier to read with less chrome |
| Monitor screens precede the cleanup jobs | Your Mac leads; Your agents groups usage and performance | Put the app's main user job first |
| Used percentage competes with free space and a large idle speed meter | Free space leads; idle throughput is compact | Answer the disk-pressure question before secondary measurement detail |
| Overview lists everything down one long column | Actionable review links, ranked agent preview, adaptive activity column | Lead to a useful next step without losing the complete dedicated screens |
| Fixed wide Worktrees columns and footer | Wide table or stacked evidence rows, wrapping action bar | Preserve every reason and action at the minimum window size |
| Two Usage charts always sit side by side | Stack when 340pt per chart is unavailable | Keep axes and model labels readable |
| 180ms page fade/scale and sidebar movement | Immediate navigation and sidebar response | Frequent and keyboard actions should not animate |
| 450ms measurement-width animation | Immediate progress measurements | Avoid layout animation on frequently updated numerical evidence |
| Cleanup subtitle describes implementation rules | Plain review instruction; exact rules remain with each action | Help the user decide without weakening protections |
| Semi-transparent secondary type and colored panel edges | Opaque secondary text and one neutral edge | Improve legibility and lower visual noise |

Motion verdict: approve the authored native changes at source level. Frequent navigation and numerical updates have no custom motion. Native progress/presentation feedback remains. UI inspection and exact standalone artifact checks are recorded separately after they run; this source review does not assert a released version.

No scanning, cleanup, Git verification, adapter, usage aggregation or service concurrency behavior is changed. Core tests remain relevant because the new entry links and layout reuse the existing observable model and confirmation paths.
