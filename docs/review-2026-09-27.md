Reviewed on 2026-09-27. This is a source review and preparation milestone. App fixes, current-bundle runtime QA, website implementation and publication are still pending.

- `/Applications/CleanMyAgent.app` is version 0.1.0, build 1. The September 15 crash report also identifies version 0.1.0. The main branch contains the earlier sidebar fix, but that does not establish current runtime stability.
- A disposable Git fixture confirmed that a clean worktree with an ignored `.env` loses that file when removed through `git worktree remove`. The fixture used dummy content only.
- No real worktrees, caches or sessions were removed. The current app test suite and native UI were not run in this review milestone.

## Recommendation

Lead with cleaning up the mess left by coding agents. Show monitoring as a useful second layer: storage, memory, local usage and observed speed. First fix the protection and command-execution defects, validate the copied standalone bundle, and publish a real download asset. Build the website around that artifact and authentic screenshots.

## Findings to fix

### P1: ignored local files can be permanently lost

`WorktreeScanner.swift:53` checks normal status, which omits ignored files. `WorktreeCleanupService.swift:71` then removes the checkout directly with Git. A unique ignored `.env`, key or local configuration can disappear even when the branch is merged and the checkout is clean. This mechanism was confirmed with a disposable Git fixture.

Add an ignored-file protection pass. Protect secret-looking or otherwise irreplaceable local files; compare duplicates against the primary checkout without logging their contents. Preserve unknown files conservatively. Test ignored secrets and unique local configuration, including changes after the initial audit.

### P1: command pipes can block scans indefinitely

`Shell.swift:41-48` waits for the process before draining stdout and stderr. A command that fills a pipe can block while the parent waits. Commands without a timeout can leave an audit stuck. With a timeout, `terminate()` followed by an unbounded wait can still hang if the child ignores SIGTERM.

Drain both output streams concurrently, close unused input, and enforce bounded termination. Add tests with output larger than pipe capacity and a child that ignores termination. Do not infer that this explains the recorded AppKit crash; the evidence points to different mechanisms.

### P1: dependency and cache cleanup uses stale process evidence

`AppModel.swift:92-99` captures worktree records and a Boolean Codex state. `RegenerableCleanupService.swift:103-120` reuses that state for every target. `validate` checks the old `hasActiveProcesses` value. A dev server or Codex instance started after the audit can therefore be missed. Non-Codex caches lack equivalent active-use checks.

Capture live process evidence immediately before each action, and fail closed if that capture fails. Test an inactive folder becoming active after preview and Codex starting between cache targets. Limit the operation to the exact paths shown in the confirmation.

### P1: failed process inspection is interpreted as inactivity

`WorktreeScanner.swift:267-269` returns an empty set when `lsof` fails. That becomes “no active process” in cleanup eligibility. Unknown evidence must protect a target, rather than make it eligible. Expose process-inspection availability in the scan result and test failure/timeout behavior.

### P1: a reused merged branch can pass the wrong HEAD check

`localCommitsAreUnpushed` can accept a newer pushed HEAD through its upstream. `safetyAssessment` then accepts any merged PR at `WorktreeScanner.swift:262`, without checking that the merged PR's `headOID` equals the current HEAD. A branch reused after a previous PR was merged can therefore be described as verified merged even though its new commits are not integrated.

Require default-branch ancestry, or an exact match with the verified merged PR head. Test reused branch names and newer pushed commits. Direct checkout removal leaves the named Git branch, but still violates the app's advertised eligibility policy.

### P1: Finder launches can fail to find GitHub CLI

`loadPullRequests` uses `/usr/bin/env gh`, which depends on the launch environment's PATH. Homebrew's `gh` may not be available to an app started from Finder even when it works in Terminal. Because unknown PR state blocks cleanup, users can get an app whose worktree action never becomes available.

Resolve common installation paths explicitly, retain unknown-state protection, and give an actionable status when GitHub CLI or authentication is missing. Test with a minimal Finder-style PATH. Bundling the Swift app does not bundle GitHub CLI.

### P2: PR lookup has an incomplete-history assumption

The query fetches at most 200 PRs and treats a missing branch as no PR. An older open PR outside that result can be missed. Match PR evidence to the specific branch or prove pagination is complete. Also avoid overwriting a newer merged PR with an older closed PR sharing the same branch name.

### P2: rapid usage-range changes can show the wrong range

`AppModel.swift:57` discards refresh requests while a scan is running. If the user changes the range again before the first scan finishes, its old result can replace the display while the picker shows the new range. Queue the latest request or discard stale results and repeat for the current selection. Test rapid 7 / 30 / 90 day changes.

### P2: scan scope and shared-worktree measurements are incomplete

Repository discovery is hardcoded to `~/dev` and depth 3. Settings displays this path but provides no editable scope. Users with projects under `~/Code`, Documents or external disks can see no worktrees. Shared worktree bytes come from another plugin's cached JSON report in `StorageScanner.swift:378`, rather than this app's current scan. A new user can see zero bytes, and an old report can remain stale.

Make scope explicit and configurable, and derive totals from current app-owned evidence. Distinguish missing/failed measurements from a verified zero. Include managed Codex worktree locations in discovery through their repositories, without assuming the founder's folder structure.

### P2: the release has no standalone artifact validation

The source workflow runs Swift tests only. The build script uses ad-hoc signing, fixed version values and duplicated resource bundles. There is no published bundle or notarization pipeline in this repository. Test the exact candidate copied outside the checkout, verify resource resolution and Finder launch, then test the downloaded release asset. Confirm both architectures before claiming universal support.

### P3: interface copy contradicts current behavior

`StorageView.swift:49` says the build has no cleanup actions, while Clean and Worktrees expose them. Settings lists only three agent homes despite eight adapters. Worktree confirmation correctly states that Git removes folders directly; the website must not claim that all cleanup uses Trash. Replace stale copy with precise current scope.

## Crash assessment

The recorded September 15 crash is `SIGABRT` on the main thread. The exception backtrace passes through AppKit constraint updates and SwiftUI hosting-view layout. It occurred in 0.1.0. Main now includes PR #3's sidebar fix and the local build script labels its output 0.1.1.

The right acceptance test is the current copied release bundle: startup, repeated sidebar toggles, all sections, window resize, menu-bar reopen, refresh, range switching, empty/unavailable data and confirmation cancellation. Record new crash reports, RSS and scan completion separately. The old crash alone does not identify a defect in the current source.

1. Disk capacity and free-space overview.
2. Storage attribution by agent, category and local path.
3. Adapters for Codex, Claude Code, Grok Build, Cursor, Hermes Agent, OpenCode, Ori and Kilo Code, with different metric coverage.
4. Attributable process RAM and process counts where detection is available.
5. Worktree audit: branch, size, Git state, PR evidence and cleanup decision.
6. Selective worktree removal after protection checks and confirmation.
7. Trash cleanup for gitignored node_modules in inactive extra worktrees.
8. Allowlisted npm, Yarn, Playwright, Puppeteer and Codex caches.
9. Archived Codex-session cleanup while Codex is closed.
10. 7 / 30 / 90 day local usage views, daily charts, token categories and models.
11. Reported costs only where local records expose them; incomplete coverage is labelled.
12. Observed throughput, TTFT and response duration where supported; live Codex throughput.
13. Menu-bar summary, manual refresh and keyboard shortcut.
14. Local scanning without application telemetry; GitHub verification is the limited network use.

Do not advertise generic system cleaning, antivirus, RAM cleaning, automatic speed improvements, uniform support for every metric, complete billing records or configurable retention that is not implemented.

## Landing-page direction

Proposed English headline: **Your AI agents make a mess. Clean it up.**

Supporting text: “Forgotten worktrees. Piles of node_modules. Caches from projects you finished weeks ago. See what is taking up space, check what needs to stay, and clear the leftovers.”

Primary action: **Download for Mac**, linked directly to a real bundled release asset. Secondary action: View source. Show version, supported macOS, architecture, license and actual signing status beside the action.

Design principles:

- Crumbs: one specific job, visible app evidence, understandable reasons before cleanup.
- SuperShrimp: short bold problem language and a friendly, playful identity.
- CleanMyMac: generous app imagery, benefits explained in human words, repeated useful download actions.
- Preserve CleanMyAgent's existing app icon and native dark interface in screenshots. Give the website a warm light canvas, confident dark typography and one coherent accent. Avoid generic icon-card grids, fake testimonials, fabricated reclaimed-space statistics or copied competitor artwork.

One-page sequence: problem and download; large real app screenshot; leftovers and cleanup steps; safety with clear lifecycle distinctions; screenshot-led feature tour; all supported agents with coverage notes; local privacy and open source; FAQ and final download.

Use sanitized real native captures. If fixture values are necessary, label them as demo data. Provide desktop/mobile validation, keyboard and reduced-motion checks. Mobbin was attempted but requires a paid plan; use the supplied references without buying a plan.

## Remediation in version 0.2.0

Implemented conservative ignored-file protection, concurrent bounded subprocess draining and forced timeout termination, fresh process/open-file checks per cache/dependency target, per-worktree revalidation, unknown-activity protection, exact merged-PR HEAD matching, remote-default integration only, branch-specific GitHub queries, explicit Homebrew CLI resolution, latest-range usage scans, configurable development folder, fresh shared-worktree measurement and corrected interface copy. Universal packaging now uses a single SPM resource bundle and proper nested resource resolution. Public demo mode disables live scans and cleanup. CI validates a copied final bundle with fixture Git data and packaged icons. Signing and notarization remain separate states.


## Validation

29 tests in 8 suites pass. The universal Developer ID signed bundle passes its copied, standalone runtime smoke: packaged icons, fixture Git audit and preservation of an ignored .env added after the audit. Native UI checks used the copied bundle with public demo fixtures: all eight sections, six sidebar toggles, normal and zoomed window sizes, 7/90/30 day switching, refresh, closing and reopening with Command-0, and cancellation of the explicit worktree confirmation. No crash occurred in this bounded run. This is not proof that every historical crash is resolved. Cleanup was never run on real user data. Intel code is packaged and verified by lipo; runtime QA was on Apple silicon. Apple notarization remains pending.

Remaining limits: repository discovery still has a bounded depth; failed size measurements can appear as zero; metric coverage varies by agent and local log format; concurrency checks cannot eliminate all filesystem races. These are documented follow-ups, not claims of completed support.
